Follow-up fixes from the independent v0.6.1 review:

- New UI-created dashboards start fresh and cannot adopt orphaned slug-named
  databases. Existing entries retain their stable database path. YAML imports
  can explicitly copy an existing database or start fresh when it does not exist.
- Migration copies compare row counts on one SQLite snapshot and carry an
  entry/source identity for safe restart before configuration persistence.
  Incomplete temporary copies are retried from the verified original. Before
  removing a managed legacy file, migration keeps a verified
  `<entry_id>.db.migrated` snapshot until that entry is removed.
- Setup failures now show their reason in HA's integration UI. Ambiguous or
  unsafe files are still rejected. Already-completed v0.6.1 migrations are not
  retroactively backed up.
- Activity records render as separate table rows. Audit fields normalize control
  characters on write and when reading existing rows; denied custom-card actions
  include the attempted entity/service.
- Configure explains that approved entities must be placed in the owner editor.
  This applies to setup-generated layouts as well as manually saved layouts.
- Concurrent card failures retain distinct diagnostic messages. Corrupt saved
  layouts show a warning and a default layout without overwriting stored data.

Back up HA before updating through HACS, then restart HA. Custom Lovelace/HACS
cards remain experimental trusted JavaScript; this release does not expand the
supported frontend API surface.
